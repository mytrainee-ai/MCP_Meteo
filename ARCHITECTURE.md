# Архитектура Weather AI Agent

## Компоненты приложения

- `streamlit_app.py` отображает чат и состояние запроса. `start.ps1` запускает Streamlit через Python из `.venv` на локальном интерфейсе.
- `src/config.py` загружает `.env` и передаёт ключ, URL провайдера, модель и адрес MCP слою сервиса.
- `src/service.py` открывает и закрывает OpenAI-клиент и MCP-сессию для одного сообщения. Оба клиента создаются внутри того же асинхронного запуска, в котором обслуживается запрос.
- `src/mcp_client.py` открывает Streamable HTTP с двумя потоками в MCP SDK 2.3.0, инициализирует сессию и получает схемы двух разрешённых инструментов. Если нужных схем нет на первой странице, клиент запрашивает следующие.
- `src/tool_adapter.py` преобразует схемы в функции для Responses API и проверяет аргументы по исходным JSON Schema. Адаптер читает структурированный ответ либо JSON из текстовых блоков. Ошибки передаются модели как отдельный результат вызова.
- `src/agent.py` выполняет цикл Responses API. Ядро принимает уже открытые клиенты и не зависит от Streamlit. Unit-тесты подставляют имитации клиентов.
- `src/conversation.py` хранит завершённые обмены одной сессии в памяти процесса. По умолчанию сохраняет восемь последних обменов. При переполнении удаляет старый обмен целиком, вместе с вызовами инструментов и их результатами.

## Обработка одного вопроса

1. Агент запрашивает схемы `geocode_location` и `get_weather_forecast`.
2. Responses API получает историю, новый вопрос и доступные функции. Агент задаёт `store=False` и запрашивает `reasoning.encrypted_content` для повторной передачи контекста рассуждающих моделей. Если модель запрашивает вызовы инструментов, Python проверяет имена и аргументы, затем передаёт разрешённые вызовы в MCP.
3. Агент добавляет результаты в историю запроса как `function_call_output` с соответствующими `call_id` и снова обращается к модели.
4. Цикл сохраняет новый обмен после получения полного текстового ответа. Ошибка или исчерпание шести обращений к модели оставляет предыдущую историю в прежнем состоянии. Сброс удаляет историю и исключает запись обмена, начатого до сброса.

## Состояние браузерной сессии

Streamlit хранит видимую переписку, экземпляр `Conversation` и обрабатываемый вопрос в `st.session_state`. При отправке вопрос сразу добавляется в переписку. На время запроса виден индикатор, поле ввода и кнопка очистки временно недоступны. После ответа ввод снова доступен. Кнопка очистки удаляет видимые сообщения и историю для модели.

## Следующие этапы

Явные тайм-ауты, отдельный лимит числа MCP-вызовов и ограничения размера результатов предусмотрены этапом надёжности. Проверка полного сценария через реальные сервисы проводится отдельно.
